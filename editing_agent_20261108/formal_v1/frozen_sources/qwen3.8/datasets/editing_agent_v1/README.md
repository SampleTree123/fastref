# Qwen 选择历史版本并调用视频编辑：第一批测试数据

## 2026-11-08：数据已准备，等待模型执行

CPU 检查已完成：7 项测试通过，用时约 2.8 秒。调试清单共 26 次编辑，128 条正式候选共 543 次编辑；前 30 条是 127 次编辑。原链中真正按画面文字回溯的情况较少：128 条里只有 8 次，其余回溯主要靠编号或编辑事件。

这批数据使用**整套服装正面、背面两张图分开提供，并给镜头编辑提供目标首帧**的版本。只写了索引，没有复制视频、转码或重新渲染。参考图和参考视频仅用于说明本轮怎么编辑；选择哪个历史版本只依据用户文字和历史记录。

| 文件 | 内容 | 用法 |
|---|---|---|
| `chains_debug.jsonl` | 6 条调试链，均来自训练分组，每条 3–5 次编辑 | 先检查选视频、编辑、保存记录整个流程 |
| `chains_test.jsonl` | 128 条按固定顺序排列的正式候选链 | 从前 30 条开始，时间充足再扩到 60、100、128 条 |
| `understanding_test.jsonl` | 1,000 道独立理解题，历史使用真实视频 | 先让 Qwen 看历史视频生成信息卡，再选择起点和整理编辑文字 |
| `private/` | 正确编号、目标视频、原图节点和属性 | 只供评分与结果页面，不能放入 Qwen 输入 |
| `audit.json` | 数量、来源文件指纹、分组和检查结果 | 核对这次具体用了什么数据 |

正式链前 30 条和前 60 条都包含七种编辑、3/4/5 次编辑长度、直链和分叉链。不是按照模型表现挑题。随机种子是 42，排序在推理开始前固定。

调试数据与正式数据按原始视频图的连通分组隔离：节点、媒体 SHA 和连通分组均不交叉。这里的分组指通过编辑边连接在一起的一组视频。原始数据中同一组不会拆到训练和测试两边。

### 1,000 道理解题具体测什么

| 选择方式 | 数量 | 例子 |
|---|---:|---|
| 用历史发色描述选视频 | 250 | 从黑头发的版本开始编辑 |
| 用历史镜头描述选视频 | 250 | 从正面近景的版本开始编辑 |
| 选择某次编辑之前 | 150 | 从第一次换衣服之前的版本开始 |
| 选择某次编辑之后 | 150 | 从第一次换衣服的结果开始 |
| 普通继续编辑 | 42 | 直接给下一次编辑要求，默认接最新版本 |
| 明确要求最新版本 | 42 | 请基于最新视频继续编辑 |
| 明确给出视频编号 | 116 | 请使用 video 2 作为起点 |

所有题都要求输出实际编号，不使用 `-1`。这批题的**本轮编辑**覆盖身份、发型、发色、服装、动作、镜头和场景七项；但**通过外观描述寻找历史**只覆盖发色和镜头两项。旧题中其他属性需要额外给一张“用于找历史”的图片，与这次规则不同，所以没有混进来。它们的缺口留给后续新题，不用缺少输入的题计算正确率。

完整链保留已有真实链的父子关系和历史选择前缀；每次编辑目标都能对应原始编辑边。检查发现旧多轮文件有些身份、发型参考仍是历史引用，因此本次把编辑文字和参考内容统一更新为当前同一编辑边的单轮清单。每处替换保存在 private 标签中；身份参考的身份编号另外与目标核对过。原数据没有被修改。理解题中的一部分历史沿用之前按真实编辑边重新组织的题，并不是一条原链原封不动的前缀；`private` 中保留了来源和是否重新组合的标记。116 道明确编号题来自真实链前缀，仅把本轮选择文字换成明确编号。

### 给模型什么，不给什么

完整链每条只包含起始视频、顺序排列的用户文字和本轮编辑参考内容。跑下一轮时，历史视频应是上一轮实际生成的结果。

理解题包含已有历史视频、每个历史视频的编号、当时从哪个编号编辑、已经执行过的编辑文字与参考内容，以及当前请求。历史父编号属于已经发生的事实；本轮正确编号不会提前提供。

信息卡由 Qwen 看视频后建立，不能用 `private` 中的真实属性代替。过去的编辑文字与实际生成结果要分开保存，避免把“要求变成黑发”误当成“画面已经是黑发”。

当前镜头参考图来自目标视频首帧，这是已确认的编辑条件；目标完整视频仍只放在 `private`。当前参考内容不能拿来替代历史选择描述。

### 怎样看结果

独立理解题使用真实历史，可以对照正确编号评分。完整生成链后面的历史已经是模型生成结果：若前面没有生成出要求的发色，后面的“从黑发版本开始”可能不再有唯一答案。因此完整链的编号统计称为 `planned_route_agreement`，表示是否走了原计划路线；遇到画面偏离后的外观选择，需要结合生成结果人工看，不能直接算成 Qwen 理解错误。

理解题和完整链可能使用相同的测试分组或视频，它们是两种测试方式，不是两份完全独立的数据。本次只做了文件、图结构、分组和输入检查，没有新增人工视频质量验收。

### 重建与检查

在项目根目录运行：

```bash
python 10_research/model_experiments/qwen3.8/scripts/editing_agent/build_dataset.py
python 10_research/model_experiments/qwen3.8/scripts/editing_agent/test_dataset.py
```

不需要 GPU，不需要安装 pytest。第二条使用 Python 自带的 unittest。

调用关系：

```text
scripts/editing_agent/build_dataset.py
  → scripts/dataset/build_selection_v3.py 的 load_graph()
    → ltx2.5/data/uedata/outfit_camera_first_frame/chains/multi_turn/chains.jsonl
    → 同版本 train / val / test / reserved 下的 samples.jsonl
  → datasets/history_selection_v3/test.jsonl
  → 检查真实编辑边、训练/测试分组、文件存在、输入不含答案
  → 本目录的 public JSONL、private JSONL 和 audit.json

scripts/editing_agent/test_dataset.py
  → 读取本目录和原始单轮清单
  → 独立核对编号、父子关系、媒体、分组、指纹与覆盖情况
```

模型入口只读取前三个公开 JSONL。`private` 与 `audit.json` 由运行程序用于评分和报告；不要整个目录直接作为模型上下文。
