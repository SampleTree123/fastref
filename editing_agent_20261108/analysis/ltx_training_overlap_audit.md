# 正式测试与LTX训练视频是否重叠

核查时间：2026-11-08T08:55:03+08:00。只读元数据，不读取大型MP4，不影响推理。

**在实际训练清单和已记录媒体SHA范围内，没有发现重叠。**正式128条链（543轮）及1000道理解题涉及的原始/历史/GT目标共1112个不同视频节点，与该LTX的训练视频在节点、文件路径、记录SHA三种比较中交集均为0。没有只依据`split=test`判断。

## 对照的确是本次LTX权重

1. 本次使用193151最终768步权重；训练记录和最终checkpoint合同一致，6个正式LTX worker记录的权重路径及SHA也与该合同相符。它从191986的50步继续，两次训练identity和采样计划完全相同；191986无续训父检查点。
2. 从冻结`sources.json`经`bindings.json`找到当时真正读取的训练清单，UE为26,326条，CoinVE为3,200条。它们的SHA与训练run记录及冻结清单一致。
3. 采样计划29,526个带来源前缀的样本编号，与两份实际清单逐项顺序一致，全部出现在完整计划内。最终记录完成768步；不是拿当前工作区另一套配置代替训练事实。
4. 训练主视频共12,380条不同路径、12,380个记录SHA；其中UE包含5,980个视频节点。正式媒体全部能匹配到冻结清单，没有缺失映射。

## 参考资产另算

正式输入共有736条不同参考资产路径，其中131条与训练参考路径相同，按记录SHA判断也是131条。共享类型/数量：`{'garment': 24, 'outfit': 16, 'hair': 24, 'identity': 16, 'motion': 45, 'scene': 6}`。这是允许重复使用的衣服、发型、身份、动作等编辑参考，不是训练主视频混入测试。全部参考类型：`{'garment': 48, 'outfit': 64, 'hair': 24, 'identity': 16, 'motion': 146, 'scene': 140, 'camera': 298}`。

镜头参考来自各自目标视频第一帧，这是已规定的输入条件；不能因此把此任务描述成没有目标视觉信息的纯文字编辑。主视频也没有以相同记录SHA进入训练参考列表。

## 能证明和不能证明什么

能证明的是：当前正式清单的1112个视频节点，和这一套LoRA实际训练清单在节点/路径/已记录文件SHA上分离；同一训练流程续训没有另混数据。不能证明官方基模预训练从未见过类似内容，也不能靠字节SHA排除重编码或视觉近似内容。本次没有重新哈希大型媒体，所以不排除媒体在清单建立后被替换；该限制明确保留。本次也未重新解码训练缓存、独立检查其中张量内容。

新生成的历史视频不是原始数据集节点。本核查检查了其对应的全部原始/GT历史，实际运行是否使用生成文件由另一个运行审查负责。已有数据audit的debug/test组隔离证据可复用，本次补的是“193151权重→冻结训练清单→具体视频”的闭环。
